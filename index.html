1. Arquitetura do Sistema

O sistema de monitoramento implementado segue uma arquitetura cliente-servidor baseada em MQTT, onde um simulador Python publica dados que são consumidos por uma aplicação cliente desenvolvida em C# (Windows Forms). A comunicação é realizada através de um broker MQTT que atua como intermediário central.

[Simulador Python] → [Broker MQTT] → [Cliente C# (Windows Forms)]

Componentes da Arquitetura:

Simulador Python (Fonte de Dados): Publica dados em formato JSON contendo os valores de Temperatura, Umidade, Pressão, Nível e Vibração. Os dados são enviados periodicamente para o broker MQTT no tópico configurado pelo usuário (padrão: industria/sensores).
Broker MQTT: Servidor central que recebe as mensagens publicadas pelo simulador Python e as distribui para todos os clientes (subscribers) conectados. O endereço e porta do broker são configurados diretamente na interface da aplicação. A configuração automática aponta para localhost na porta 1883.
Cliente C# (Windows Forms): Aplicação desenvolvida em C# com interface gráfica usando Windows Forms. Conecta-se ao broker MQTT, assina o tópico configurado e exibe as informações recebidas em tempo real. Possui sistema de alarmes visuais para condições críticas de temperatura e vibração.

Dados Monitorados:

Campo Tipo Descrição Propriedade JSON
Temperatura double Valor de temperatura em °C Temp
Umidade double Valor de umidade relativa Umi
Pressão double Valor de pressão Pres
Nível double Valor de nível do processo Level
Vibração double Valor de vibração em mm/s Vib

2. Protocolo MQTT

O MQTT (Message Queuing Telemetry Transport) é um protocolo de mensagens leve baseado em publicação/subscrição, ideal para comunicação em ambientes com largura de banda limitada e dispositivos com recursos restritos. É amplamente utilizado em IoT e automação industrial.

Conceitos Fundamentais:

Broker: Servidor central que gerencia todas as conexões MQTT. Recebe mensagens de publishers e as distribui para subscribers interessados. O endereço e a porta são configurados pelo usuário na interface da aplicação.
Tópico (Topic): String hierárquica que funciona como canal de comunicação. Publishers enviam mensagens para tópicos, e subscribers recebem ao se inscreverem. O tópico padrão configurado automaticamente é industria/sensores.
Publisher: Cliente que publica mensagens em um tópico. No projeto: Simulador Python que envia dados de sensores industriais.
Subscriber: Cliente que se inscreve em tópicos para receber mensagens. No projeto: Aplicação C# que consome e exibe os dados em tempo real.

Configuração MQTT do Projeto:

Parâmetro Valor (Automático) Observação
Broker localhost Configurável manualmente via campo txtBroker
Porta 1883 (padrão MQTT) Configurável manualmente via campo txtIP
Tópico industria/sensores Configurável manualmente via campo txtTopic
Formato de Dados JSON Desserializado com Newtonsoft.Json

Vantagens do MQTT:

  • Protocolo leve com baixo overhead de rede
  • Comunicação desacoplada entre publishers e subscribers
  • Suporta múltiplos níveis de QoS (Quality of Service)
  • Ideal para redes com largura de banda limitada
  • Escalável para milhões de dispositivos simultâneos
  • Implementação simples e rápida

3. Aplicação Cliente em C# (Windows Forms)

A aplicação cliente foi desenvolvida em C# utilizando Windows Forms. Conecta-se ao broker MQTT, recebe dados em tempo real, exibe as informações em uma interface gráfica e dispara alarmes visuais para condições críticas de operação.

Tecnologias Utilizadas:

  • .NET (Windows): Framework de desenvolvimento da Microsoft
  • Windows Forms: Framework para criação de interfaces gráficas desktop
  • MQTTnet: Biblioteca C# para comunicação MQTT (via MqttFactory e IMqttClient)
  • Newtonsoft.Json (Json.NET): Biblioteca para desserialização de JSON

Modos de Conexão:

Conexão Automática (btnAuto): Preenche automaticamente os campos txtBroker com localhost, txtTopic com industria/sensores e txtIP com 1883, e já aciona a conexão em seguida.
Conexão Manual (btnManual): Desconecta qualquer sessão ativa, limpa todos os campos de configuração e o painel de alertas, e redefine o status de conexão para "Pendente" — aguardando preenchimento manual pelo usuário.
Desconexão (btnDisconnect): Encerra a conexão com o broker se o cliente estiver conectado e atualiza o indicador de status para "Desconectado".

Fluxo de Funcionamento:

  1. Usuário configura o Broker, Porta e Tópico (manualmente ou via botão Automático)
  2. Usuário clica em "Conectar" ou usa a conexão automática
  3. Aplicação instancia um IMqttClient via MqttFactory e registra o handler de recebimento de mensagens
  4. Aplicação conecta ao broker e assina o tópico configurado
  5. Cada mensagem recebida é decodificada de UTF-8, desserializada de JSON para o objeto DadosMqtt
  6. Os valores são exibidos nos labels correspondentes de forma thread-safe via Invoke()
  7. Alarmes são verificados e registrados no richTextBoxAlertas com timestamp
  8. A barra de progresso de temperatura (pBarTemp) é atualizada e redesenhada

Tratamento de Thread-Safety:

Como a aplicação recebe mensagens em uma thread separada (thread do MQTT), a atualização da interface gráfica é feita de forma thread-safe utilizando Invoke(MethodInvoker). Isso garante que todas as atualizações de UI ocorram na thread principal da aplicação, evitando exceções de acesso cruzado.

Tratamento de Erros de Conexão:

A lógica de conexão está encapsulada em um bloco try/catch: em caso de sucesso, o label lblConnection exibe "Conectado" em verde escuro; em caso de falha, exibe "Desconectado" em vermelho.

4. Componentes da Interface Gráfica

A interface é composta por controles de configuração de conexão, indicadores de leitura em tempo real, uma barra de progresso vertical customizada para temperatura e um painel de alertas.

Campos de Configuração MQTT

Componentes:
  • txtBroker — Endereço do broker MQTT (ex: localhost)
  • txtIP — Porta de conexão (ex: 1883)
  • txtTopic — Tópico MQTT a ser assinado (ex: industria/sensores)
  • lblConnection — Indicador de status: Pendente, Conectado ou Desconectado

Botões de Ação

Componentes:
  • btnConnect — Conecta ao broker com os dados informados nos campos
  • btnDisconnect — Desconecta do broker
  • btnAuto — Preenche automaticamente os campos e conecta
  • btnManual — Limpa campos, reseta alertas e status para preenchimento manual
  • btnSaibaMais — Abre esta documentação no navegador

Indicadores de Sensores

Componentes (labels):
  • lblTemp — Exibe o valor de Temperatura em °C
  • lblUmi — Exibe o valor de Umidade
  • lblPres — Exibe o valor de Pressão
  • lblLevel — Exibe o valor de Nível
  • lblVib — Exibe o valor de Vibração em mm/s (muda para vermelho em alarme)

Barra de Progresso Vertical (VerticalProgressBar)

Componente: pBarTemp — Barra vertical customizada que representa visualmente o nível de temperatura.

Implementação: Classe VerticalProgressBar (herda de ProgressBar) com renderização manual via OnPaint. A barra cresce de baixo para cima, com fundo cinza claro e preenchimento colorido.

Comportamento de cor:
  • 🟢 Verde (LimeGreen) — temperatura abaixo de 75°C (operação normal)
  • 🔴 Vermelho (Red) — temperatura igual ou acima de 75°C (alarme ativo)
Escala: Mínimo 0, Máximo 100. O valor é limitado a 100 via Math.Min(). O redesenho é forçado via pBarTemp.Invalidate() a cada mensagem recebida.

Painel de Alertas

Componente: richTextBoxAlertas — Caixa de texto formatada que acumula o histórico de alarmes disparados durante a sessão.
Formato das entradas: [HH:mm:ss] TIPO ALARME: valor unidade
Limpeza: O painel é esvaziado automaticamente ao acionar o botão Manual (btnManual).

5. Estrutura de Dados Recebidos

Os dados são transmitidos pelo simulador Python em formato JSON e desserializados pela aplicação C# para objetos da classe DadosMqtt, definida dentro da própria Form1.

Exemplo de Mensagem JSON:

{
  "Temp": 68.5,
  "Umi": 45.2,
  "Pres": 1013.1,
  "Level": 72.0,
  "Vib": 12.3
}

Classe DadosMqtt (C#):

Definição da classe interna:

public class DadosMqtt
{
  public double Temp { get; set; }
  public double Umi { get; set; }
  public double Pres { get; set; }
  public double Level { get; set; }
  public double Vib { get; set; }
}

Mapeamento de Propriedades:

Propriedade JSON Propriedade C# Tipo Descrição
Temp Temp double Temperatura em graus Celsius
Umi Umi double Umidade relativa
Pres Pres double Pressão do processo
Level Level double Nível do processo
Vib Vib double Vibração em mm/s

6. Sistema de Alarmes

A aplicação implementa verificação automática de condições críticas a cada mensagem recebida. Quando um limiar é ultrapassado, um alerta com timestamp é registrado no painel richTextBoxAlertas e o indicador visual correspondente é alterado.

Alarme de Temperatura Alta

Condição: dados.Temp >= 75
Ação: Registra alerta no formato [HH:mm:ss] TEMPERATURA ALTA: {valor}°C e muda a cor da pBarTemp para Vermelho.
Normalização: Abaixo do limiar, a barra retorna à cor Verde (LimeGreen).

Alarme de Vibração Alta

Condição: dados.Vib >= 18 (mm/s)
Ação: Registra alerta no formato [HH:mm:ss] VIBRAÇÃO ALTA: {valor} mm/s e muda a cor do label lblVib para Vermelho.
Normalização: Abaixo do limiar, o label retorna à cor Preta.

Resumo dos Limiares:

Sensor Limiar de Alarme Indicador Visual Mensagem Gerada
Temperatura ≥ 75°C Barra pBarTemp fica vermelha TEMPERATURA ALTA: {valor}°C
Vibração ≥ 18 mm/s Label lblVib fica vermelho VIBRAÇÃO ALTA: {valor} mm/s
