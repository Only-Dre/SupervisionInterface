1. Arquitetura do Sistema

O sistema de monitoramento implementado segue uma arquitetura cliente-servidor baseada em MQTT, onde um simulador Python publica dados que são consumidos por uma aplicação cliente desenvolvida em C# (Windows Forms). A comunicação é realizada através de um broker MQTT que atua como intermediário central.

[Simulador Python] → [Broker MQTT] → [Cliente C# (Windows Forms)]

Componentes da Arquitetura:

Simulador Python (Fonte de Dados): Publica dados em formato JSON contendo contador, temperatura e um novo sinal. Os dados são enviados a cada 2 segundos para o broker MQTT no tópico industria/sensores.
Broker MQTT: Servidor central que recebe as mensagens publicadas pelo simulador Python e as distribui para todos os clientes (subscribers) conectados. No projeto, o broker está configurado no IP 10.110.18.11 na porta 1883.
Cliente C# (Windows Forms): Aplicação desenvolvida em C# com interface gráfica usando Windows Forms. Conecta-se ao broker MQTT, assina o tópico de dados e exibe as informações recebidas em tempo real, além de manter um histórico de leituras.

Dados Monitorados:

Campo Tipo Descrição Propriedade JSON
Contador int Número sequencial de mensagens recebidas contador
Temperatura double Valor de temperatura em °C com precisão de 1 casa decimal temperatura
Novo Sinal int Terceiro parâmetro adicionado conforme atividade prática novo_sinal

2. Protocolo MQTT

O MQTT (Message Queuing Telemetry Transport) é um protocolo de mensagens leve baseado em publicação/subscrição, ideal para comunicação em ambientes com largura de banda limitada e dispositivos com recursos restritos. É amplamente utilizado em IoT e automação industrial.

Conceitos Fundamentais:

Broker: Servidor central que gerencia todas as conexões MQTT. Recebe mensagens de publishers e as distribui para subscribers interessados. No projeto: 10.110.18.11:1883
Tópico (Topic): String hierárquica que funciona como canal de comunicação. Publishers enviam mensagens para tópicos, e subscribers recebem ao se inscreverem. No projeto: industria/sensores
Publisher: Cliente que publica mensagens em um tópico. No projeto: Simulador Python que envia dados de sensores.
Subscriber: Cliente que se inscreve em tópicos para receber mensagens. No projeto: Aplicação C# que consome os dados.

Configuração MQTT do Projeto:

Parâmetro Valor
Broker IP 10.110.18.11
Porta 1883 (padrão MQTT)
Tópico industria/sensores
Formato de Dados JSON
Intervalo de Publicação 2 segundos
Sessão Limpa Habilitada

Vantagens do MQTT:

  • Protocolo leve com baixo overhead de rede
  • Comunicação desacoplada entre publishers e subscribers
  • Suporta múltiplos níveis de QoS (Quality of Service)
  • Ideal para redes com largura de banda limitada
  • Escalável para milhões de dispositivos simultâneos
  • Implementação simples e rápida

3. Aplicação Cliente em C# (Windows Forms)

A aplicação cliente foi desenvolvida em C# utilizando Windows Forms, uma framework de desktop tradicional da Microsoft. A aplicação conecta-se ao broker MQTT, recebe dados em tempo real e os exibe em uma interface gráfica intuitiva.

Tecnologias Utilizadas:

  • .NET 10.0 (Windows): Framework de desenvolvimento moderno da Microsoft
  • Windows Forms: Framework para criação de interfaces gráficas desktop
  • MQTTnet: Biblioteca C# para comunicação MQTT
  • Newtonsoft.Json (Json.NET): Biblioteca para desserialização de JSON

Fluxo de Funcionamento:

  1. Usuário insere as configurações MQTT (Broker, Porta, Tópico) na interface
  2. Usuário clica no botão "Conectar"
  3. Aplicação cria um cliente MQTT e estabelece conexão com o broker
  4. Aplicação se inscreve no tópico industria/sensores
  5. Broker começa a enviar mensagens para a aplicação
  6. Cada mensagem recebida é desserializada de JSON para objeto C#
  7. Dados são exibidos em labels na interface (thread-safe)
  8. Histórico de leituras é mantido em uma lista
  9. Usuário pode desconectar clicando em "Desconectar"

Classe de Dados (DadosMqtt):

Estrutura JSON recebida:

{
  "contador": 1,
  "temperatura": 25.5,
  "novo_sinal": 42
}

Mapeamento C#:
Contador → int
Temperatura → double
NovoSinal → int

Tratamento de Thread-Safety:

Como a aplicação recebe mensagens em uma thread separada (thread do MQTT), a atualização da interface gráfica é feita de forma thread-safe utilizando Invoke() com MethodInvoker. Isso garante que todas as atualizações de UI ocorram na thread principal da aplicação.

4. Componentes da Interface Gráfica

A interface foi organizada em três painéis principais, cada um com uma função específica no sistema de monitoramento.

Painel 1: Cabeçalho (Header)

Função: Exibir o título da aplicação
Componentes: Label com texto "Cliente MQTT" em fonte grande e negrita
Estilo: Fundo azul claro (SystemColors.ActiveCaption)

Painel 2: Configurações MQTT

Função: Permitir configuração de conexão ao broker
Componentes:
  • txtBrocker - TextBox para endereço IP do broker (ex: 10.110.18.11)
  • txtPorta - TextBox para porta MQTT (ex: 1883)
  • txtTopico - TextBox para tópico MQTT (ex: industria/sensores)
  • btnConectar - Botão para iniciar conexão
  • btnDesconectar - Botão para encerrar conexão

Painel 3: Dados Recebidos

Função: Exibir os dados recebidos do broker em tempo real
Componentes:
  • lblContador - Label exibindo o contador (int)
  • lblTemperatura - Label exibindo temperatura formatada com 1 casa decimal (°C)
  • lblNovoSinal - Label exibindo o novo sinal (int)
Estilo: Fonte grande (21-25pt) e negrita para destaque

Histórico de Leituras:

Componente: lstHistorico - ListBox que mantém registro de todas as mensagens recebidas
Formato: [HH:mm:ss] Contador: X | Temp: Y °C | Sinal: Z
Comportamento: Novas leituras são inseridas no topo da lista (Insert(0, ...))

5. Estrutura de Dados Recebidos

Os dados são transmitidos pelo simulador Python em formato JSON e desserializados pela aplicação C# para objetos da classe DadosMqtt.

Exemplo de Mensagem JSON:

{
  "contador": 42,
  "temperatura": 28.5,
  "novo_sinal": 156
}

Mapeamento de Propriedades:

Propriedade JSON Propriedade C# Tipo Descrição
contador Contador int Sequência de mensagens (incrementa a cada envio)
temperatura Temperatura double Valor de temperatura em Celsius (faixa: 20-90°C)
novo_sinal NovoSinal int Terceiro parâmetro adicionado na atividade prática

Formatação de Exibição:

  • Contador: Exibido como inteiro simples (ex: 42)
  • Temperatura: Formatada com 1 casa decimal e unidade (ex: 28.5 °C)
  • Novo Sinal: Exibido como inteiro simples (ex: 156)
  • Timestamp: Adicionado automaticamente ao histórico (HH:mm:ss)

Tratamento de Erros:

Se a desserialização JSON falhar ou os dados forem inválidos, a mensagem é ignorada silenciosamente. Se houver erro de conexão, uma mensagem de erro é exibida ao usuário em um MessageBox.
